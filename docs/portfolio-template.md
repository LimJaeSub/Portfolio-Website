# 포트폴리오용 기록

> **이 파일의 용도**
> 이 프로젝트를 나중에 포트폴리오 사이트에 추가하기 위한 기록이다.
> 작업하면서 그때그때 채운다. 다 만든 뒤 몰아서 쓰지 않는다.
>
> **작성 원칙**
> - 개발 일지는 **막힌 그 순간에** 쓴다. 일주일 지나면 세부사항이 사라진다.
> - 없는 내용은 비워둔다. 채우려고 지어내지 않는다.
> - 커밋 메시지를 그대로 옮기지 않는다. 막혔거나·선택했거나·배운 것만 쓴다.
>
> **옮기는 방법**
> 포트폴리오 레포에서 이 파일을 Claude Code에 주고
> "CLAUDE.md 데이터 스키마에 맞춰 projects.js에 추가해줘"라고 요청한다.

## 작성 시 주의

**실무(`work`) 프로젝트인 경우**
- 고객사명·제품명·내부 문서·스크린샷은 포함하지 않는다
- 사용한 도구·기법·프로세스와 본인 역할까지만 기술한다
- 판단이 애매하면 "무엇을 했는가"까지만 쓰고 "무엇을 발견했는가"는 뺀다

**이 프로젝트가 SDLC 과정을 밟지 않는 경우**
- 기획·이슈 섹션은 비워둔다
- 개발 일지 대신 `## 회고`로 제목을 바꾸고 날짜 없이 주제별로 쓴다
  (사후에 돌아보며 쓴 글을 '개발 일지'로 표기하지 않는다)
